# Solo — The Card Game (web: hotseat and online)

Built only from the designer's rulebook and card spreadsheet (`source/`), `readings.md` and the owner's `rulings.md`.

## Play
Double-click `index.html`. Pick a seed, a character and a deck style for each player, then **Start game**. Hand the device over when the "Pass the device" screen appears.
Tick **Debug mode** on the setup screen for the card/stat editor (both hands visible, no pass screen).

The **Game log** (right side, or the bottom of the screen on a phone) shows what just happened and why, newest first. Each player only sees their own hidden cards named (lines in blue are details only you can see).

## Play online (two computers)
1. One player opens the game, picks **Online**, chooses a character and clicks **Host**. They get a 5-letter room code and a join link.
2. They send the code (or the link) to their friend. The friend opens the game, picks **Online**, chooses a character, enters the code and clicks **Join**.
3. Play. Each player only sees their own screen's prompts; the other sees "Waiting for opponent…". The bar at the top shows the connection: *Opponent connected*, *Reconnecting…* or *Opponent disconnected*.

- The host's browser runs the game, so the host should keep their page open.
- If the friend's connection drops (or they refresh), they come back automatically on refresh, or by joining again with the same code.
- If the host refreshes, the game is rebuilt from the saved seed and moves, and the friend reconnects by themselves. If the host closed the browser, **Online → Resume hosting room …** brings the game back (same browser only).
- No installs and no server of ours: the browsers connect directly (WebRTC) using [PeerJS](https://peerjs.com) and its free public broker. See `report-online.md` for what's tested and the known limits.

## Put the game online for free
The game is static files, so any static host works. Both options below give you an `https://` address to send to your friend.

**GitHub Pages**
1. Push this folder to a GitHub repository (it can be public or, on a paid plan, private).
2. On GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, choose `main` and `/ (root)`, **Save**.
3. After a minute the game is at `https://<your-user>.github.io/<repo-name>/`. Tests are at `.../tests.html`.

**Cloudflare Pages**
1. In the Cloudflare dashboard: **Workers & Pages → Create → Pages**, then either connect the GitHub repository or choose **Upload assets** and drag in this folder.
2. Leave the build command empty and the output directory as `/`. Deploy.
3. The game is at `https://<project-name>.pages.dev/`.

**How the friend joins:** send them the address plus the room code, or just the join link the host sees (it looks like `https://…/index.html#join=ABCDE`). Both players must load the same version of the game: after you update the site, both should refresh, or the game will refuse to connect with a "Version mismatch" message.

## Test
- Open `tests.html` in a browser: 200 tests (one per card, core rules, the action log, and online play with a simulated host and guest), shown as a pass/fail list.
- Command line: `node tools/run-tests.js`, or `powershell -ExecutionPolicy Bypass -File tools\run-tests.ps1` (headless Chrome or Edge).

## Files
- `js/engine.js`: rules engine. `Solo.apply(state, action)` is the only way to change the game.
- `js/effects.js`: every card and character ability.
- `js/cards-data.js`: generated by `tools/build-cards.ps1` from the spreadsheet + readings.md + rulings.md.
- `js/online.js`: online play without the network (host/guest sessions, messages, the filtered view each player is sent).
- `js/net.js`: connects those sessions over PeerJS.
- `js/ui.js`, `style.css`, `index.html`: the UI (hotseat and online).
- `decisions.md`: choices made where the sources were unclear. `report.md`: per-card results and known doubts. `report-online.md`: online play: what works, what's untested, limits.

# Decisions

Choices made while building the game where the rulebook, `readings.md` and `rulings.md` didn't settle the question. `rulings.md` wins over `readings.md`. All 20 rule interpretations in `readings.md` §1 were confirmed by the owner and are implemented as written; this file only lists the *extra* choices.

## Project / process
- **Inputs.** The rulebook, spreadsheet and `rulings.md` were copied into `source/`, so the repo is self-contained. `readings.md` is at the repo root.
- **Git.** The folder was already a git repository (one "Initial commit"), so I used it instead of running `git init` again.
- **Card data** is generated by `tools/build-cards.ps1` from the spreadsheet (names, colors, numbers, original text) plus each card's line in `readings.md`. The three rulings (Lion Finisher, Sun Cross, Forest Oak) replace their readings text. Output: `js/cards-data.js`.
- **Card names** are built as Family + Move (e.g. "Phoenix Chop") from each sheet's "Color Type Names" column. This fixes typos like "PhoenixChop" and fills the seven blank Black "Death" names, following readings.md.
- **Card ids**: `R`ed / Bl`U`e / `Y`ellow / `G`reen / blac`K` + number + family (e.g. `K3-death`). Characters are `C-` + first name (e.g. `C-asher`).
- **Decks.** There's no deck builder. Each player picks a character and "character's color" or "all colors"; the seed then picks 20 different cards × 2 copies = 40.
- **Previewing.** `tools/serve.ps1` is a small local server used only for automated checks. The game itself runs by double-clicking `index.html`.

## Engine architecture
- All state is one JSON object. `Solo.apply(state, action)` returns a new state or an error; the input state is never changed.
- **Choices** (pick a card, yes/no, a number) pause the action: `state.pending` holds the choice and the half-finished action. The next `{type:'choose'}` action re-runs the original action from its saved starting state with all the answers so far. This keeps every state plain JSON, so it's easy to send over a network later, and keeps replays exact.
- **Randomness** (the first player, shuffles, random discards) comes from a mulberry32 generator whose state is stored in `state.rng`. The same seed and the same actions always give the same game.
- A **mandatory choice with only one legal option** is made automatically, without asking.
- **Hidden-information choices** (e.g. the opponent choosing cards to discard for Phoenix Uppercut) are asked of that player. The UI shows the pass-the-device screen first.

## Turn / round flow
- **Setup:** the first player is picked at random from the seed. Both players draw 5. The first player decides on a mulligan, then the second.
- **Engage:** the player picks how many to draw (0, 1 or 2), then discards that many from their whole hand. If the deck runs short, they discard only as many as they actually drew.
- **Feint action:** only Blood Cross and Blood Uppercut have an action-menu Feint. Using one ends your turn, and it breaks an "engage, engage" chain.
- **Clash start / end effects:** the round's first player resolves first — character ability, then combo cards left to right — then the other player.
- **Clash win** triggers (Vlad, Phoenix Snap) resolve right after damage.
- **Reset** order: (0) energy refills to max (or stays higher if a bonus pushed it above max) and power resets to 0; (1) each player, first player first, discards any cards and draws up to 5; (2) end-of-clash effects; (3) combos go to their owners' discard piles, except kept cards (Phoenix Roundhouse, River Roundhouse, Ink Finisher), which stay in the combo in order as the leftmost cards; (4) if any deck is empty, the game ends.
- **Death check** happens after each effect finishes, so "you lose 2 and your opponent loses 2" (Flame Chop) is one simultaneous step. Both at 0 or less = draw.
- **Face-down cards discarded from a combo** stay face down in the discard pile. Every other discard is face up unless the card says otherwise.
- **Who controls a card** ("you" on the card) is the player whose combo it's in. A card planted in the opponent's combo works for them. "When discarded" effects belong to the card's owner, since the card goes to the owner's pile.
- **Returning a card "to your hand"** puts it in the named player's hand, and that player becomes its owner.
- **Order when a card is played:** (1) its combo enter (including Patience); (2) the player's character "when you play" ability; (3) other cards that watch for plays: Mantis Straight, Ink Roundhouse, Umbra Straight, then the opponent's Mantis Uppercut. "When you play" abilities also fire for cards played from the discard or deck, but not for cards that are only *put* into a combo.
- **Copying a combo-enter ability** (Cyber Chop, Forest Finisher): "this card" in the copied text means the copying card. Copy effects can't copy each other (prevents loops).

## Card-level choices (beyond readings.md)
- **Flipping** only means face up → face down. Cards turned face up (Flash Cross, Lion Roundhouse, Death Snap, Evelyn) trigger nothing.
- **Flash Jab** is offered on every flip of one of your combo cards except flips you chose yourself (Patience, River Roundhouse, Death Straight). **Life Jab** is offered only on flips caused by the opponent. **Mantis Jab** is offered only when the opponent's effect discards one of your combo cards.
- **Sun Cross** (ruling): offered whenever you discard another card (from hand, combo or deck top), if that card is still in your discard pile. The Sun Cross's own discard doesn't trigger another Sun Cross.
- **Lion Hook / Lion Finisher / Sun Cross** count discards where *you* are the one discarding: engage, reset, your own effects, and effects that tell you to discard (e.g. Dante makes the opponent discard from their own deck). Discards done *to* you by the opponent's effect (Sun Roundhouse) count for the opponent.
- **Umbra Straight** / **Ink Roundhouse** / **Mantis Straight** don't trigger on themselves being played. **Mantis Uppercut** fires when the opponent plays a card with printed value 4 or less.
- **Values in text** ("next to a 3", "a 5 or less") use the card's current value: face-down = 0, or 2 with Noct Umbra, +3 per Death Finisher. Numbers a character checks when a card is played ("odd number", "Red number less than 4") use the printed number.
- **"The first card"** = leftmost; **"the last card"** = rightmost.
- **Planting cards** (Umbra Chop, Ink Straight, Death Cross, Death Uppercut) may use any card from your discard pile, face up or face down. It goes into the opponent's combo face up, and at cleanup it returns to your discard pile.
- **Flame Straight**: only face-up discard cards can be chosen. Choosing none is allowed.
- **Phoenix Uppercut**: the opponent sees the damage amount, then picks which cards to discard.
- **Flame Snap** with Flame Uppercut: the "lose all but 1 life" becomes a life *gain* of the same amount.
- **Check Finisher**: four separate flips, each of any face-up card in either combo (yours included).
- **Forest Hook**: with only 1 card left in the deck, that card is played. Nothing is discarded.
- **Life Hook**: the "card next to it" is its left neighbor (it's always rightmost when it enters). With no neighbor, nothing happens.
- **Life Uppercut**: true when your lowest combo value is greater than the opponent's highest (always true if their combo is empty).
- **Life Snap**: random discards use the seeded generator. The player whose hand it is counts as the discarder.
- **Death Roundhouse**: pick 1s one at a time (each must be a new color) or stop. They're played in the order picked.
- **Ink Finisher**: its combo enter discards it. Its end-of-clash "stay" only matters if it's in a combo without having resolved combo enter (planted, put there by Leo Wildheart, or blocked by Ink Uppercut).
- **River Roundhouse**: if the flip is prevented (Umbra Roundhouse, Life Jab, Flash Jab), the card isn't kept.
- **Evelyn Shadow**: the start-of-clash reveal hits both combos. Revealed cards count their printed number but have no abilities (shown as "no abilities") until cleanup.
- **Leo Wildheart**: the deck card is put in face up with no combo enter, as readings.md says. The even-number return is optional.
- **Jack Spades**: a pair is the played card with the same value as the card directly to its left.
- **Dante**: at 5 colors, both the 3-color and 5-color effects happen.
- **Flash Finisher**: the whole discard pile, including Flash Finisher itself, is shuffled into the deck.
- **Sun Cross** only returns **your own** cards. If you discard an opponent's combo card (e.g. with Sun Roundhouse), Sun Cross isn't offered; otherwise it would steal their card.
- **Hidden information**: a face-down card returned to a hand is logged as "a face-down card". The full state object still contains both hands. That's fine for one shared screen, but online play will need the server to send each player a filtered view.

## Tests
- `tests.html` runs everything in the browser. `tools/run-tests.ps1` runs the same page in headless Chrome/Edge from the command line (Node isn't installed on this machine) and writes `test-results.json`.
- Tests build exact board positions with `T.setup`, act only through `Solo.apply`, and answer prompts by card id. A test fails if a prompt it expects doesn't appear, or one it doesn't expect does.

## Action log (spec stage "Action log")
- **Built by the engine.** `log()` in `js/engine.js` writes entries into `state.log` while an action resolves, so the log replays exactly with the seed + action list and will work the same online. The UI only renders `Solo.logView(state, viewer)`.
- **Entry shape.** `{ t, p?, pt?, src?, k?, dbg? }`. `t` is the public text. If `p` is set, player `p` reads `pt` instead (e.g. `pt` = "Player 1 draws 2 cards: Red 3 Flame Straight, ...", `t` = "Player 1 draws 2 cards."). So every entry is public, or public with a private version for one player. I chose one entry with two texts rather than two separate entries so both players see the same number of lines in the same order.
- **Who may see a hidden card's name:** its owner (`card.owner`), the same rule the board already used. This covers drawn cards, face-down cards put into a combo, face-down discards, face-down cards returned to hand, Phoenix Roundhouse keeping a face-down card, and debug edits to hidden zones. Face-up discards, plays and face-up puts are public (they are public on a real table).
- **Source of each line.** Card and character abilities run inside `trigger(name, fn)`, which prefixes every line they log with the source, e.g. "Check Roundhouse (end of clash): ...", "Cyber Jab (when flipped): ...", "Blood Cross (Feint): ...". If an ability logs nothing, the engine adds "no effect." Character "when you play" abilities are checked on every play, so they only log when they fire.
- **Failed conditions** are logged for conditional card abilities ("Blood Straight: not next to a 3, so nothing happens.", "Check Roundhouse (end of clash): Player 1 dealt 4 damage, so no draw."). Character conditions that fail on an ordinary play are not logged (noise).
- **Reactions** (Flash Jab, Life Jab, Mantis Jab, Sun Cross, Mantis Uppercut) log both "used" and "doesn't use it", since declining is visible at a real table.
- **Wording** uses "Player 1 / Player 2", not "you", so the same text works on a shared hotseat screen. Stat lines show the new value ("gains 2 life (now 12)"). Card plays show cost, any cost change (Ink Chop, Blood Snap, the card's own discount) and why the placement is legal.
- **Hotseat display.** The log shows the current device holder's view; with "show both hands" (debug) it shows everything. Newest first, scrollable, sticky beside the board on wide screens and pinned to the bottom of the screen on narrow ones.
- **Existing tests:** three assertions read `state.log` as strings. They now use `T.logText` / `T.logHas` (same checks, new log format), and the "face-down card returned to hand" check now asserts the *opponent's* view doesn't name the card (the owner's view now does, on purpose).
- **Leak test.** `tests/log.test.js` plays 20 random games and checks after every action that no line in a player's view names a card that player hasn't been able to see. Public reveals inside one action (a card discarded face up, then taken back by Sun Cross) count as seen.
- **Test runner.** Node is now installed on this machine, so `node tools/run-tests.js` runs the same tests without a browser. `tools/run-tests.ps1` stopped working because Chrome now writes a warning to stderr; it now ignores stderr from the browser.

## Online play (spec stage "Online play")
- **Split.** `js/online.js` has everything except the network: `HostSession`, `GuestSession`, the messages, and `viewFor(state, viewer)`. `js/net.js` only moves those messages over PeerJS. This is what lets the tests run whole online games in Node with an in-memory pipe.
- **Seats.** The host is always Player 1, the guest Player 2. Who goes first is still random (from the seed). Each player picks their own character and deck style; the guest's choice travels in its `hello` message and the host builds both decks.
- **The host picks the seed**: 20 random characters from `crypto.getRandomValues`, so it can't be guessed. It is never sent to the guest. Before cards get ids, each deck list is shuffled again using the secret seed, because `buildDeck` lists the two copies of a card 20 places apart and the ids would otherwise pair them up.
- **What the guest receives** (`viewFor`): keys are whitelisted, so a new state field stays private unless added on purpose. Removed: the opponent's hand, both decks (order and identity; only the count is shown), the opponent's face-down cards in combos and discard piles (id and uid), the seed, the generator state, and the pending choice's saved base state, answers and action. A choice's options go only to the player who must choose; the other gets `{ player }` and shows "Waiting for opponent…". The log is the Stage 1 log rendered for that player.
- **The host renders its own filtered view too**, so both screens use exactly the same code path and the host's screen also can't show the guest's hidden cards by mistake. (The host's browser still holds the full state; see limits.)
- **The log is sent incrementally**: each `state` message carries only the new log lines; a rejoining guest gets the whole log again.
- **Legality**: the guest sends `{ type, ... }`; the host forces `player: 2`, allows only play/engage/feint/choose, and runs `Solo.apply`, which already rejects moves out of turn or for the wrong player. Refusals go back as an `error` message and are shown on the guest's screen.
- **Version check**: both sides compare `Solo.VERSION` (in `js/engine.js`). The host refuses a `hello` with a different version and the guest refuses a `welcome` with a different version. It must be bumped by hand when rules, cards or messages change.
- **Rejoining**: the guest's browser keeps a random seat token per room (localStorage). Joining with the same token takes the seat back. A *different* token may take the seat only while it is empty (so a friend who switched devices can still get back in). A third person is refused while the seat is taken.
- **Restoring the host**: after every move the host saves `{ config (seed + decks), actions, guestToken }` to localStorage, and `Solo.replay` rebuilds the state. sessionStorage remembers "this tab was hosting room X / playing as guest in room X", so a refresh goes straight back into the game without mixing up two tabs of the same browser.
- **Disconnect detection**: WebRTC can take a long time to notice a closed tab, so both sides send a ping every 3 s and drop the connection after 12 s of silence. The guest retries every 3 s. After a refresh the broker may still hold the host's room id for a while, so a restoring host keeps retrying the same code; a brand-new room just picks a different code.
- **Debug mode is off online**: the debug panel isn't shown, and the host session refuses `debug` actions from either player.
- **No pass-the-device screen online**; each screen is one player's.
- **PeerJS** 1.5.4 is loaded from unpkg.com only when you click Host or Join, so hotseat still works offline by double-clicking `index.html`.
- **Known, accepted limit**: the host's browser holds the full game state (both hands, deck order). A host who opens the developer tools can see everything. The guest can't.
